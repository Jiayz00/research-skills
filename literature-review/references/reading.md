# 阅读与证据提取（reading）

## 先决定读哪几篇

- discovery 的结果是候选集，不是结论集。
- 默认选 3–5 篇 load-bearing 论文：直接回答问题、提供关键方法、代表不同 family、或给出与主流相反的证据。
- 如果用户只要“找论文/推荐阅读”，可以停在 ranked discovery；一旦要比较、综述或支持 claim，就必须读原文。
- 不要为了凑数量读十篇摘要；读透少数关键论文，比生成一页浅摘要更有价值。

## 读什么

按顺序提取：

1. **问题与设定**：任务、数据、假设、评价指标。
2. **方法**：关键机制、训练/推理流程、依赖的组件。
3. **实验**：baseline、数据集、compute、超参、评测协议。
4. **结果**：主结果、消融、失败案例、限制。
5. **可迁移性**：哪些部分可应用到当前项目，哪些依赖特殊数据/算力。
6. **局限与冲突**：作者承认的限制、与其他论文的矛盾、未解决的问题。

只读摘要时，最多说“候选/作者声称”；不要说“论文证明了”。

## claim-level evidence

- 每个外部 claim 至少对应一条可定位的证据：章节、图号、表号、页码或原文段落。
- 引用原文时保留完整语境；不要拼接不同 snippet，不要把省略号当作忠实的连接。
- 数值、指标、benchmark 名称要回到原文；不从二手博客或摘要推断。
- 区分作者原话、你的解释、项目里的推论。三者不要混在一个引用后面。
- 如果找不到原文或权限受限，明确说“未能核验”，而不是用相近论文顶替。

## 版本与来源

- 记录版本：arXiv v1/v2、会议版、期刊版、DOI、发布日期。
- 优先引用与用户问题匹配的版本；如果预印本和正式版结论不同，明确说明。
- 打开原始 PDF/HTML 后再摘录；搜索结果的 snippet、引用页和摘要页只能用于发现。
- 论文主页、代码仓库、数据集页面是辅助 provenance；不要把仓库 README 当作论文正文证据。

## 多篇阅读笔记

每篇至少记录：

```markdown
## <paper title> (<year>, <venue/version>)
- DOI/arXiv/PMID:
- 来源与链接:
- 问题:
- 方法:
- 关键结果（带图表/章节位置）:
- 限制:
- 与当前项目的关系:
- 可复用/不可复用的部分:
```

- 笔记保持可搜索；不要把整篇论文粘进上下文。
- 读完后先写一页以内的证据摘要，再开始综合；避免边读边写导致结论漂移。
- 对多篇论文做 comparison matrix 时，用同一组维度：问题、数据、方法、指标、compute、限制、适用条件。

## 引用与配额

- 引用跟随句子：谁提出、谁验证、谁限制。
- 直接引用要少而准；能转述的不要整段搬。
- 每条引用都能从真实来源打开；不要生成看似合理但无法访问的 URL。
- 如果只能找到二手来源，明确标注二手，并把它降级为线索而不是结论。
