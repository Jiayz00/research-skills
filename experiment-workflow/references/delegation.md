# 子代理委派

适用于你的 harness 支持子代理 / 后台会话时。核心原则：**只委派真正独立的工作，并给出自包含的 brief。**

## 该派什么

- 合适：调研陌生代码库、整理已完成的写作、彼此无关的数据处理、已选定论文的独立阅读/摘要。
- 不合适：实验循环里你正在等的关键步骤——那一步自己做，不要外包后再干等。
- 检索与选文的主判断留在主代理：候选的排序、取舍、最终引用核验不要外包。
- 实验结果分析的主判断留在主代理：可以让子代理独立复算/交叉检查，但不要把最终 `repair/refill/promote/stop` 决策外包。
- 委派前先确认这件事与当前节点的工作没有重叠，避免两边改同一批文件。

## 保护分支与运行

- 绝不把主会话正在使用的分支交给子代理修改；要改实验代码，让它自己开分支（或按本技能的建节点流程开自己的分支）。
- 冻结节点谁都不得修改。
- 明确写清子代理**允许发起哪些运行**；不允许时直接写“不要发起任何运行”，否则它会默认自己可以跑实验。
- `optimization-advisor` 的只读诊断边界同样适用于子代理：不改 tracked files、不安装依赖、不跑完整训练。
- 子代理的改动留在它自己的工作区，不会被自动合并——检查与合入是主代理的活。
- 嵌套与并发上限按你的 harness 规则执行；被拒绝就自己做或等已有子代理结束。

## 写自包含的 brief

子代理从空白上下文开始，看不到你的对话。brief 至少包含：

- 仓库路径与相关分支 / 节点；
- 目标指标、baseline 与约束；
- 允许的动作（可以运行什么、不可以运行什么）；
- 需要读取的 analysis/proposal/日志路径；
- 期望产出与“完成”的定义。

多段 brief 一次写全，不要依赖它猜。

## 文献与外部证据

- 检索循环、query 调整、候选排序和最终 citation 核验由主代理负责。
- 可以委派“读某一篇已选定论文并提取指定字段”，但必须检查它引用的原文位置。
- 社区/工程搜索可以并行收集，但 Tier 分级、适用性审查和 proposal 排序由主代理完成。
- 不允许子代理生成没有打开过的 DOI、引用或社区结论。

## 并发与清理

- 遵守并发上限，不要无限派发。
- 用完的子代理及时关闭 / 清理，不要堆积。
- 子代理返回后：检查产物 → 决定合并或采纳 → 关闭。
