# 综合与输出（synthesis）

先决定用户要的是哪一种输出；不要默认写一篇长综述。

| 用户意图 | 输出模式 | 停止点 |
| --- | --- | --- |
| 找论文、推荐阅读 | ranked discovery | 返回排序后的候选、为什么入选 |
| 解释概念/比较方法 | guided synthesis | 先给结论，再用 3–5 篇关键论文支撑 |
| 写 related work | thematic review | 按主题组织，不按论文逐篇罗列 |
| 做方法选型 | comparison matrix + recommendation | 给出适用条件、成本、风险 |
| 找研究缺口 | gap analysis | 区分“没人做”和“我没找到” |
| 写论文引用 | evidence table + BibTeX | 每条引用可核验 |

## Ranked discovery

每条包含：

- 标题、作者、年份、venue、版本；
- DOI/arXiv/PMID 和可打开链接；
- 一句话说明为什么与问题相关；
- 来源和排序依据；
- 如果需要，再给“读这篇时看什么”。

不要给没有实际检索到的论文编号或引用；不要用模型记忆补全候选。

## Guided synthesis

结构：

1. 一句话回答或比较结论；
2. 2–4 个关键证据点，每条带原文位置；
3. 分歧、限制和不确定性；
4. 对当前项目的含义；
5. 可选：下一步该读/试什么。

- 先让读者看到结论，再展开证据。
- 把“作者声称”和“实验证明”分开。
- 对冲突结果，呈现条件差异而不是强行投票。

## Related work

按主题/方法 family 组织：

```markdown
## <theme>
- **共同设定**：...
- **代表工作**：<paper> 提出了...；证据在 <figure/table/section>。
- **差异**：...
- **仍未解决**：...
- **与本文的关系**：...
```

- 不要逐篇摘要；每个主题回答“这组工作共同建立了什么、还缺什么”。
- 不要把 unrelated citations 堆在同一段。
- 引用密度服务于论证，不服务于数量。

## Comparison matrix

| 维度 | 论文 A | 论文 B | 论文 C |
| --- | --- | --- | --- |
| 问题/设定 | | | |
| 数据/规模 | | | |
| 方法 | | | |
| 指标/结果 | | | |
| compute/成本 | | | |
| 限制/适用条件 | | | |
| 版本/证据位置 | | | |

- 单元格里写事实和出处，不写泛泛评价。
- “未报告”要写清楚，不要填猜测。
- matrix 之后给 recommendation：在什么条件下选谁，为什么。

## Gap analysis

- 先列出已覆盖的主题/方法/评测。
- 再写缺口：数据、设定、规模、评测、失败模式、可复现性。
- 每个缺口附证据：哪些论文没有覆盖、覆盖到什么程度。
- 区分：
  - **真正空白**：多个可靠来源都未涉及；
  - **检索空白**：当前 query/source 没找到，不能断言不存在；
  - **饱和领域**：已有大量工作，继续做需要新的角度。

## BibTeX 与引用

- 每条 BibTeX 必须有真实标题、作者、年份和 DOI/arXiv/PMID 之一。
- key 稳定可读：`firstauthorYYYYshorttitle`；重名加字母后缀。
- 不伪造 `journal`、`volume`、`pages`；缺失字段留空或用 `note` 说明。
- 论文使用 bib 工作流时输出 `refs.bib`；否则给可嵌入的 `thebibliography` 条目。
- 交付前逐条打开 URL/DOI，确认记录存在且与引用句子匹配。

## 交付前的核验清单

- [ ] 每条引用都能打开并指向真实记录。
- [ ] claim-level 结论有原文位置，不只是摘要。
- [ ] 版本（预印本/会议/期刊）标注清楚。
- [ ] 冲突和限制没有被省略。
- [ ] 没有把社区讨论伪装成同行评议证据。
- [ ] 没有编造作者、年份、DOI、引用数或结果。
